序：你要学会的不是一块板子

这是一套从“会写软件”走到“能读懂、编译、烧录、调试多板硬件系统”的入门路线。主案例来自 Multi-Function-ESP32-Debugger，包含 ESP32-C6 主机、多个 ESP32-S3 仪器模块和一个 ESP32-C3 陀螺仪模块。

完整书稿请打开仓库中的 book.md。本页面提供在线阅读入口和核心章节导航。

建议：先通读第 1～5 章，再照第 14 章做实验。不要一开始就买齐所有硬件。

你会得到什么

  • 理解固件、启动链、FreeRTOS 任务和 ESP-IDF 组件。
  • 能解释 UART、SPI、I²C、USB、ESP-NOW 和 SWD 的角色。
  • 能从 C6_Screen、S3_LogicAnalyser、S3_Thermal 等工程反推系统架构。
  • 能用 AI 做源码导航、根因分析和小步验证。

最快上手路径

编译 → 单板启动 → 两板 UART → LinkIt 握手 → 一个传感器 → UI → 无线 DAP

总线与协议的核心观念

UART 是字节流，SPI 是带时钟的主从事务，I²C 是带地址和寄存器语义的共享总线，SWD 是调试器到目标 MCU 的调试链路。把它们混为“串口”是最常见的入门错误。

层本项目例子先验证什么
电气3.3 V、GND、TX/RX、SDA/SCL供电、共地、电平、引脚
驱动UART、SPI、I²C、USB初始化和波形
协议LinkIt、instrument frame、DAP长度、序号、CRC、状态机
应用波形、热图、环境数据、SWD数据是否正确路由

把项目读懂

阅读顺序不要从最大的 main.c 开始。先看根目录 README，再看各工程的 CMake 和 sdkconfig.defaults，随后进入 shared/linkit_sdk、shared/instrument_protocol，最后跟一个具体模块的数据流。

练习：画出“MLX90640 → S3_Thermal → LinkIt → C6_Screen → LVGL”的数据流，并在每条箭头旁写明数据格式。

用 AI，而不是被 AI 牵着走

每次提问都给目标、约束、现象和验收方式。让 AI 把结论分成源码证据、数据手册证据、测量证据和推测。AI 可以解释寄存器，但不能替你确认线有没有接错。

四周实践计划

  1. 第 1 周：安装 ESP-IDF，编译一个工程，读懂 CMake。
  2. 第 2 周：烧录 GPIO 和串口示例，完成两板 UART 回环。
  3. 第 3 周：读取一个 I²C 传感器，写带 CRC 的小帧协议。
  4. 第 4 周：编译 C6 与 S3 模块，跟踪一帧数据到 UI。
